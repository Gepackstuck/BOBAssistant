# Разведка телевизора (этап 0)

Дата: 2026-11-18. Телевизор TCL 85RM7L, Google TV, Android 14 (SDK 34), SoC MediaTek MT9689.
Все проверки делались по ADB и только на чтение, кроме двух тестов сна.

## Сон

| Что проверяли | Результат |
|---|---|
| `input keyevent KEYCODE_SLEEP` | `mWakefulness=Asleep`, ТВ отвечает на ping, ADB работает, 7 минут без изменений |
| `KEYCODE_POWER`, как кнопкой на пульте | То же: Asleep, ТВ в сети |
| Причина сна | `mLastSleepReason=screenless_mode`: экран выключен, Android работает |
| Глубокий сон (suspend) | Не было: `uptime` совпадает с `elapsedRealtime` за 4.6 дня работы, ночи тоже |
| Сетевой режим ожидания TCL | `tcl_sys_network_standby_enabled=0`, но он и не нужен |

**Вывод.** Выключенный с пульта ТВ продолжает работать. Приложение может слушать микрофон
и включать экран само. Raspberry Pi и Wake-on-LAN не нужны.

## Low Power Standby

Когда ТВ выключен с пульта, включается режим Google TV **Low Power Standby**: сеть остаётся только
у приложений из списка исключений (Google Assistant, Chromecast, Netflix и т. п.). Наше приложение
получало `blocked=LOW_POWER_STANDBY` и не могло соединиться с Маком (тайм-аут TCP), хотя из оболочки
ADB Мак был доступен. Команды, чтобы добавить приложение в исключения, нет.

Решение на сейчас: `settings put global low_power_standby_enabled 0` (откат: `... 1`).
Позже Боб станет системным ассистентом (этап 10), которому исключение положено.

## Микрофон

| Что | Результат |
|---|---|
| Вход | `AUDIO_DEVICE_IN_BUILTIN_MIC`, стерео (маска `0xc`), 16 кГц |
| Эхо | Есть вход `AUDIO_DEVICE_IN_ECHO_REFERENCE`, 16 кГц: звук самого ТВ для эхоподавления |
| Кто слушает при включённом экране | `com.google.android.katniss` (Google Assistant): `AUDIO_SOURCE_HOTWORD` и `ECHO_REFERENCE`, распознаёт программно, не через SoundTrigger |
| Кто слушает во сне | Никто: katniss отпускает микрофон |
| SoundTrigger | Сессий нет |

**Вывод.** Во сне микрофон свободен. При включённом экране Android 10+ по правилам совместного
доступа должен отдавать звук и нам, и «Ok Google». Это проверим тестовой сборкой на этапе 2.
Вход эха позволяет вычитать звук фильма из микрофона.

## Плеер Кинопоиска

`ru.kinopoisk.tv` поставлен на паузу, читаем `dumpsys media_session`:

- `actions=7340029`: есть `SEEK_TO`, `PLAY_PAUSE`, `PLAY`, `STOP`, `FAST_FORWARD`, `REWIND`
  (так объявляет медиасессия, а работает ли это на деле, проверим на этапе 6);
- `position` приходит, по нему можно перематывать «на N минут»;
- `metadata` без названия, поэтому «что за фильм?» через медиасессию не получится.

## Окна и разрешения

| Что | Результат |
|---|---|
| Размытие под окном | Нет (`mBlurEnabled=false`). Плашка будет полупрозрачной, с тоном и светлым краем |
| `SYSTEM_ALERT_WINDOW` | Операция есть, выдаётся через `appops set` |
| Слушатель уведомлений | `cmd notification allow_listener` работает |

## Память

2.4 ГБ всего, около 1 ГБ свободно. Приложение на ТВ должно быть лёгким, тяжёлая работа идёт на Маке.

## Заметки по ADB на Маке

- macOS не пускает `adb`, запущенный из терминала без разрешения «Локальная сеть», к ТВ
  (`No route to host`, хотя ping проходит). Сервер `adb` нужно запускать из Terminal.app.
- После отзыва авторизаций нужно заново выполнить `adb pair` (код на ТВ: «Отладка по Wi-Fi»
  → «Подключить устройство с помощью кода»).

## Урок: микрофон ТВ очень тихий и легко «зависает»

- Драйвер записывает **32-битный** звук. Запись в `PCM_16BIT` теряет младшие биты, и речь приходит с пиком около 50
  из 32768 (−56 дБ). Запись в **`PCM_FLOAT`** плюс усиление примерно в 60 раз даёт пик ~2000 и rms ~550, то есть нормальную речь.
  Усиление хранится в приложении и задаётся без пересборки: `am start -n com.bobassistant.tv/.MainActivity --ef gain 60`.
- **Переустановка приложения во время записи** (`adb install -r`, `am force-stop`) оборвала запись, и входной поток
  `audio_flinger` завис (`Thread may be deadlocked`). Микрофон отдавал нули, пока ТВ не перезагрузили. Теперь
  приложение умеет останавливать запись штатно: `am broadcast -a com.bobassistant.tv.STOP -n com.bobassistant.tv/.ControlReceiver`
  (принимает только оболочка, работает и на заставке, и во сне). После этого проверить, что запись остановлена:
  `dumpsys media.audio_policy | grep 'uid <uid приложения>'` должно быть пусто, и только потом ставить обновление.
  Команда `am start ... --ez stop true` не срабатывает, пока ТВ показывает заставку.
- После **`am force-stop`** Android не шлёт приложению `BOOT_COMPLETED`, пока его не откроют вручную.
- **Перезагрузка возвращает `low_power_standby_enabled` в 1.** Его нужно выключать заново.
- После перезагрузки Android сам выключает «Отладку по Wi-Fi», порт меняется. Сопряжение при этом сохраняется.
- `adb reboot` надо проверять по аптайму (`cat /proc/uptime`), а не по тексту «готово».
- **Android 14 не даёт запускать микрофонный сервис из `BOOT_COMPLETED`.** После перезагрузки приложение само не стартовало.
  Теперь после загрузки запускается невидимая прозрачная активность, а уже из неё сервис (так можно), экран ТВ при этом не включается.
- **Заглушённая запись не возвращается из `read`.** Через 5 секунд после остановки сервиса Android глушит микрофон приложения
  (`App op 27 missing, silencing record`), блокирующее чтение зависает навсегда, запись остаётся «активной». Остановка
  теперь вызывает `AudioRecord.stop()`, которое прерывает чтение, а новая запись не стартует, пока жив старый поток.
  Запуск второй записи поверх застрявшей (`start: status -110`) вешает аудиодрайвер.
